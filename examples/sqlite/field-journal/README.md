# Field Journal Example

This example is a small offline field journal for recording wildlife observations
on a laptop or field device. It uses an existing file-backed SQLite database and
demonstrates the TypeScript SQL builders generated by `sqlay` without introducing a
SQLite driver dependency into generated code.

The example keeps its SQL readable and executable as ordinary SQLite SQL:

- `sql/observations.sql` contains a site observation list and a single-observation
  lookup. The list has an optional `quickFilter` Slot.
- `sql/observation_filters.sql` contains the Slot's global Fragments: an unreviewed
  filter, a species-name Param filter, and a Repeat-backed observation ID filter.
  This Fragment-only file does not produce a generated TypeScript file.
- `sql/mutations.sql` contains natural `INSERT ... VALUES`, `UPDATE ... WHERE`, and
  `DELETE ... WHERE` builders, plus a Repeat-backed bulk tag insert.

`field_journal_observations.individual_count` is an SQLite `INTEGER`. The example
config maps that column to TypeScript `number` because this application constrains an
observation count to a small safe integer. This override changes TypeScript
annotations only; it does not convert values, validate inputs, or configure a
database driver.

## Create the database

Run these commands from this directory:

```sh
sqlite3 field-journal.sqlite3 < schema.sql
sqlite3 field-journal.sqlite3 < seed.sql
export FIELD_JOURNAL_DATABASE_URL='sqlite://field-journal.sqlite3'
```

The relative SQLite URL resolves from the process working directory, not from the
directory containing `sqlay.config.json`. The file must exist before `sqlay` runs;
`check` and `compile` do not create it. This example uses only the file's `main`
schema.

With an installed `sqlay` binary, validate or generate the builders with:

```sh
sqlay check
sqlay compile
```

From a repository checkout, the equivalent commands are:

```sh
cargo run --locked --manifest-path ../../../Cargo.toml -- check
cargo run --locked --manifest-path ../../../Cargo.toml -- compile
```

`check` runs the full SQLite-backed pipeline and renders generated TypeScript in
memory without writing files. Generated builders return SQL text and ordered params
only. Choosing and configuring the SQLite driver, executing statements, and managing
transactions remain application responsibilities.

The generated files under `generated/` are committed compiler output. The example
check creates a database only in a temporary project copy, regenerates the builders,
compares them byte for byte with the committed output, and runs `tsc --noEmit` plus
the builder SQL and params assertions.
